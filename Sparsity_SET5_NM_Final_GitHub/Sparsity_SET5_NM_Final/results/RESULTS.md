# 팀원 스파시티 원본 적용 후 재검증 결과

2026-11-19 · Vivado Simulator 2022.2 · ACC 4세트 · PE 4×4 · folding=0 · clock=10ns. 이번 RTL로 새로 컴파일하고 실제 Verilog 시뮬레이터를 실행했습니다.

## 변경 범위와 원본 보존

- `rtl/sparsity_frontend.v`: 팀원 첨부 파일과 **바이트 단위 동일**. 변수명·포트명·내부 로직 수정 없음.
- `rtl/gemm_top.v`: 이전 완성본에서 `NM_ENABLE` 파라미터 선언과 스파시티 인스턴스의 해당 override만 제거.
- `gemm_control.v`, `operand_loader.v`, `result_writer.v`, `mac_array_compute_nm.v`: 이전 완성본과 바이트 단위 동일. 이번 수정에서 다른 팀 회로는 변경하지 않음.
- 기존 MAC 파일에 이미 있던 세미콜론 한 글자 문법 패치는 유지. 새로 MAC을 수정한 것이 아님.
- 출처/보존 검사는 `verify_sources.py`, 이번 수정 전 해시는 `reference/revision.json` 참조.

## 검증 범위

- 확장·원본 대조·작은 버퍼 시험: **414회 측정 실행**. 각 안에서 새 NM 69회 + 원본 69회. 안마다 확장 입력 62개와 작은 버퍼 입력 1개이며 반복·reset 검증을 포함.
- 최대 크기 64×128×1024: 새 NM의 1·2·3안 모두 추가 통과. 본 검증 417회에 업로드 직전 6회 추가 검사를 합쳐 **총 423회**.
- 전체 C를 독립 Python 정수 행렬곱과 대조. 실제 발행 수와 nonzero MAC 수도 독립 계산값과 일치.
- 원본 대비 **189개 case/안 조합**에서 수락된 메모리 요청의 A/B 구분·주소 순서가 모두 동일. inspection은 메모리팀 기대 순서로도 확인.
- 별도 스파시티 검사 **65,728개 그룹** 통과: 모든 열별 B bitmap 조합 65,536개 + 짧은 K·끝 행 192개.
- 이전 완성본과 공통인 **405회 측정 행은 모든 지표가 동일**. 새 bank_zero 입력을 추가했고 이전 압축 OFF 대조군은 이번 최종본에서 제거.
- 합성/Fmax/전력 측정은 수행하지 않음.

## round와 ACC bank 충돌 검사

테스트벤치는 누산이 이어지는 모든 수락 패킷에서 `dut.cbank === dut.compute.cur_idx`를 검사합니다. bank 하나의 A가 전부 0인 bank_zero, B 전체가 0인 중간 그룹, 부분 bank, K=1, 짧은 K, 첫/마지막 제어 패킷, 출력 stall을 포함하여 실패가 없었습니다.

`first=last=1`인 완결 타일은 물리 ACC0을 바로 재사용할 수 있으므로 위 물리 bank 번호 일치 조건에서는 제외합니다. 이 경우도 실제 C 결과와 출력 안정성은 검사합니다.

연결 규칙은 모든 유효 bank에 동일한 round 수를 round→bank 순서로 발행하는 것입니다. A가 0인 bank도 패킷을 생략하지 않고 work_mask=0으로 전달합니다. 현재 MAC은 out_bank를 직접 받지 않습니다.

## HTML의 2-of-4 입력 비교

기존 메모리팀 HTML의 A/B 생성식을 그대로 사용. 메모리 지연=1, 입력/출력 stall=0, INT8 scalar 1개 요청·outstanding 1개 모델. 주소별 지연 차이는 없습니다.

|---|---|---:|---:|---:|
| 1안 | 20×12×8 | 920→880 | 120→60 | 1,920→924 |
| 1안 | 8×8×4 | 236→240 | 16→8 | 256→128 |
| 1안 | 19×11×7 | 791→744 | 105→60 | 1,463→706 |
| 1안 | 64×128×128 | 205,882→204,002 | 65,536→32,768 | 1,048,576→507,328 |
| 2안 | 20×12×8 | 1,390→1,392 | 120→60 | 1,920→924 |
| 2안 | 8×8×4 | 364→368 | 16→8 | 256→128 |
| 2안 | 19×11×7 | 1,161→1,156 | 105→60 | 1,463→706 |
| 2안 | 64×128×128 | 303,090→302,306 | 65,536→32,768 | 1,048,576→507,328 |
| 3안 | 20×12×8 | 1,390→1,392 | 120→60 | 1,920→924 |
| 3안 | 8×8×4 | 364→368 | 16→8 | 256→128 |
| 3안 | 19×11×7 | 1,161→1,156 | 105→60 | 1,463→706 |
| 3안 | 64×128×128 | 303,090→302,306 | 65,536→32,768 | 1,048,576→507,328 |

기본 1안은 20×12×8에서 9.20→8.80µs입니다. 작은 입력은 그룹 수집 대기로 사이클이 늘기도 합니다. 패킷 감소와 전체 시간 감소를 구분해야 합니다. 메모리 읽기 수와 순서는 원본 그대로이며, 2·3안은 기존 prefetch bridge의 중계 비용을 유지합니다.

MAC 수는 event_mac으로 센 마스크가 켜진 논리 PE 연산 항입니다. 원본은 0과 곱하는 항도 포함하고 새 NM은 A/B가 모두 nonzero인 항만 포함합니다. 원본의 nonzero 항 개수는 새 NM과 같습니다. 태그에 의한 일반 MUL/특수 연산 구분은 전력이나 물리 multiplier 토글 측정이 아닙니다.

이전 버전의 같은 NM MAC 압축 OFF 비교에서는 20×12×8이 882→880사이클이었습니다. 원본 대비 920→880의 차이 전체를 N:M만의 이득으로 해석하면 안 됩니다. 이 수치는 이전 버전에서 수행한 참고 결과이며 이번 최종본에는 OFF 옵션이 없습니다.
