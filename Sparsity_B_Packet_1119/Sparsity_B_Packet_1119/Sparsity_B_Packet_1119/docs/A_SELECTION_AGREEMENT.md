# A 선택 위치와 MAC 연결 합의사항

기록일은 2026-11-18이다. 스파시티·MAC 팀이 A 선택의 담당 위치와 데이터 전달 규약을 맞추기 위한 기록이다.

## 현재 확정한 내용

- 이번 변경은 스파시티의 K 선택 출력 추가다.
- 기본 4열에서 `out_k_mask`는 8비트다. 0열은 [1:0], 1열은 [3:2], 2열은 [5:4], 3열은 [7:6]을 사용한다.
- 각 필드는 그룹 내부 K=0~3을 나타낸다.
- A 선택의 담당 위치와 A 그룹 전달 방식은 팀 간 추가 합의 대상이다.

## 현재 코드가 하는 일

현재 스파시티는 연속 K 네 위치의 A·B를 버퍼에 모은다. 각 B 열의 모드와 위치 비트맵에서 이번 라운드의 K를 골라 `out_k_mask`로 내보낸다. 기존 `out_a`에는 해당 K로 이미 선택한 열별 A 벡터가 나온다. 기본 4×4에서 `out_a`는 128비트다.

`out_k_mask`와 B·태그·실행 마스크는 같은 `out_valid/out_ready` 패킷으로 전달된다. `out_k`는 그룹 시작 K다. 원래 K는 `out_k + out_k_mask[2*c +: 2]`로 구한다.

계산 항이 없는 열은 K 필드가 0이며 B 태그와 해당 열의 PE 실행 마스크도 0이다. K 필드의 0은 K=0을 가리킬 수도 있으므로 실행 여부는 태그·실행 마스크를 함께 보고 판단한다.

## A 선택을 맡는 위치별 구성

| 항목 | 스파시티에서 A 선택 | MAC에서 A 선택 |
| --- | --- | --- |
| A 저장 및 선택 | 스파시티가 ACC별 A 그룹을 저장하고 열별로 선택 | MAC이 ACC별 A 그룹을 저장하고 열별 K로 선택 |
| 발행 때 A 전달 | 선택된 A 벡터 4개를 128비트로 전달 | 미리 저장한 A 그룹을 열별 K 2비트로 조회 |
| 필요한 A 그룹 | 스파시티 내부에 저장 | MAC이 선택할 수 있도록 별도 경로로 전달·저장 |
| 현재 코드와 연결 | 현재 `out_a`를 사용 | MAC의 A 그룹 수신 규약을 정한 후 연결 |

예를 들어 같은 패킷에서 0열이 K=0, 1열이 K=3을 선택하면, 0열은 A의 K=0 벡터를, 1열은 A의 K=3 벡터를 써야 한다. 각 곱의 A와 B는 같은 K에 대응해야 한다.

## 팀 간 합의할 항목

| 항목 | 합의할 내용 |
| --- | --- |
| A 선택 담당 | 열별 A 선택기를 스파시티에 둘지 MAC 입력부에 둘지 결정한다. |
| A 그룹의 전달 경로 | MAC이 로더 스트림에서 직접 저장할지, 스파시티가 모은 그룹을 전달할지 결정한다. |
| A 그룹의 폭과 순서 | 기본 4행×4K의 A 그룹은 ACC 하나당 16 B다. 32비트씩 4회 전달할지 128비트로 한 번에 전달할지와 행·K 비트 배치를 정한다. 4 ACC의 전체 A 값은 그룹당 64 B다. |
| 그룹과 ACC 식별 | A 데이터와 압축 B 패킷이 같은 타일·그룹·ACC에 속하도록 식별 규칙을 정한다. 그룹 시작 K와 ACC 번호는 다른 타일에서도 재사용되므로 버퍼 교체 순서를 함께 정의한다. |
| A 수신 완료와 발행 시작 | A 그룹 저장 완료 전에 해당 그룹의 K 선택 패킷을 소비하지 않도록 그룹 수신 핸드셰이크 또는 ready 규칙을 정한다. |
| 버퍼 교체와 정체 | 현재 그룹의 마지막 패킷 수락 시점, 다음 그룹 저장 가능 시점, 두 그룹 버퍼 사용 여부를 정한다. valid=1·ready=0 동안 선택 대상 A 그룹과 K·B·태그·마스크를 유지한다. |
| A nonzero 판정과 PE 마스크 | 스파시티가 선택 K에 맞춰 현재처럼 `work_mask[4*r+c]`를 보낼지, MAC이 선택한 A에서 nonzero를 판정해 실행 마스크를 만들지 결정한다. |
| 무효 열 | 현재의 ZERO 태그와 0 실행 마스크로 판정할지, 별도 열 valid를 추가할지 결정한다. |
| 타일·그룹 경계 | first/last는 타일 초기화·완료를 나타낸다. K 네 개 그룹의 수신·교체 경계와 구분해 연결한다. 중간 0:4 그룹의 생략과 경계의 0 마스크 패킷 처리를 맞춘다. |
| 실제 포트 이름과 설정 | MAC의 K 입력 포트 이름과 A 그룹 입력 포트, ready 경로를 공유해 top 연결을 확정한다. 기존 열별 A를 받는 경로는 `A_PER_COLUMN=1`, `FACTORED_MASK=0`, `PE_Folding=0`으로 검증했다. |

현재 `out_group_end`는 그룹 관측 이벤트다. 중간 0:4 그룹에서도 발생하며 A 데이터 수신용 ready가 붙어 있지 않다. MAC의 A 그룹 저장 완료 신호로 사용할 경우에는 수락 규약을 추가로 설계해야 한다.

## 비트 폭과 효율을 비교할 기준

한 ACC에서 K 네 개의 A 그룹은 128비트다. 스파시티가 열별 A를 선택하면 발행마다 A 128비트를 보낸다. MAC이 A 그룹을 한 번 저장하면 그룹당 A 128비트와 발행마다 K 선택 8비트를 전달하는 구성이 가능하다.

2라운드 그룹의 A·K 정보량은 각각 256비트와 144비트다. 이는 그룹 전달 횟수를 포함한 데이터량 계산이다. 실제 포트 폭은 직렬·병렬 전달 방식에 따라 정해지고, 전체 사이클은 그룹 수집과 버퍼 정체에 따라서도 달라진다.

## 연결 후 공동 검증

1. 같은 라운드의 열마다 서로 다른 K를 고르고 A·B가 정확히 짝지어지는지 검사한다.
2. 0:4·1:4·2:4·Dense와 K 끝부분, A가 0인 행, 무효 B 열을 검사한다.
3. ACC 순회와 first/last, 한 라운드 타일, 중간 0:4 그룹 생략을 검사한다.
4. A 그룹 수신 또는 MAC 소비가 정체될 때 데이터 유지와 버퍼 교체를 검사한다.
5. 재시작·reset 이후 그룹 상태와 C 결과를 검사한다.
6. 메모리팀 HTML 입력으로 C 정답, MAC 발행 수, 전체 사이클을 다시 비교한다.

현재 8비트 K 선택 출력 추가본은 Vivado에서 64개 그룹 검증을 통과했다. 검증 대상은 기존 선택 A 출력과 새 K 출력의 정합성이다. MAC팀이 A를 저장·선택하는 구현과의 통합 검증은 위 인터페이스 합의 후 진행한다.
